ÉTAPE 4 : Éxécuter PinGetName pour récupérer les infos sur l'instruction candidate

Le fichier data/log/analyse.log doit contenir une ligne au format :
    Reg: <NOM_REGISTRE> Lib: <NOM_DLL> Delta: <OFFSET_DECIMAL>
Exemple :
    Reg: REG_RCX Lib: libssl-3-x64.dll Delta: 123456

$PIN_TOOL="C:\Users\diala\Downloads\pin-external-4.0-99633-g5ca9893f2-clang-windows"

Le résultat sera dans data/log/getName.log

ÉTAPE 5 : Éxécuter Backtracer pour capturer la backtrace au point d'extraction

Le fichier data/log/getName.log (généré à l'étape 4) doit contenir :
    Librairie: <NOM_DLL>
    Delta: <OFFSET_DECIMAL>
    Adresse: 0x<ADRESSE_HEX>
    Fonction: `<NOM_FONCTION>`
    Instruction: <DESASSEMBLAGE>

$PIN_TOOL="C:\Users\diala\Downloads\pin-external-4.0-99633-g5ca9893f2-clang-windows"
& "$PIN_TOOL\pin.exe" -t "C:\Users\diala\OneDrive\Bureau\Projet 2A\On reprend\inside-msteams\Pintools\MyPintool\obj-intel64\Backtracer.dll" -- Cible/curl.exe https://www.google.com

Le résultat sera dans :
  - data/log/Backtrace.log       (backtrace complète avec pile d'appels)
  - data/log/backtrace_leaks.log (logs de debug et octets extraits)

================================================================================================================================
ÉTAPE 6 : Reconstruire le fichier ssl-key.log (SANS SSLKEYLOGFILE)

Cette étape permet de reconstruire les secrets TLS à partir des leaks capturés,
sans avoir besoin de la variable SSLKEYLOGFILE.

A) Récupérer le Client Random depuis Wireshark :
   - Filtre : tls.handshake.type == 1
   - Naviguer vers : TLS → Handshake Protocol: Client Hello → Random
   - Copier les 32 bytes (64 caractères hex)

B) Exécuter le script de reconstruction :
python Scripts/reconstruct_keylog.py -i Data/log/backtrace_leaks.log -r <CLIENT_RANDOM_HEX> -o Data/decryption-key.log -v

Exemple avec Client Random :
python Scripts/reconstruct_keylog.py -i Data/log/backtrace_leaks.log -r 1234567890abcdef1234567890abcdef1234567890abcdef1234567890abcdef -o Data/decryption-key.log -v

Le fichier Data/decryption-key.log contiendra les 5 secrets TLS 1.3 au format SSLKEYLOGFILE.

================================================================================================================================
ÉTAPE 7 : Déchiffrer le trafic dans Wireshark

1. Ouvrir le fichier de capture (.pcap ou .pcapng)
2. Aller dans : Edit → Preferences → Protocols → TLS
3. Dans "(Pre)-Master-Secret log filename" → sélectionner Data/decryption-key.log
4. Cliquer sur OK
5. Le trafic TLS est maintenant déchiffré !

================================================================================================================================
NOTES IMPORTANTES

Candidat validé pour curl + OpenSSL 3.x + TLS 1.3 :
  - DLL      : libcrypto-3-x64.dll
  - Delta    : 3656159 (0x37C9DF)
  - Fonction : SHA384_Final

Positions des secrets TLS dans les leaks (stables) :
  - Position 11 : SERVER_HANDSHAKE_TRAFFIC_SECRET
  - Position 30 : SERVER_TRAFFIC_SECRET_0
  - Position 36 : EXPORTER_SECRET
  - Position 39 : CLIENT_HANDSHAKE_TRAFFIC_SECRET
  - Position 53 : CLIENT_TRAFFIC_SECRET_0

Endianness :
  - ssl-key.log stocke les secrets en little-endian par blocs de 8 octets
  - Les leaks capturés sont en big-endian
  - Le script reconstruct_keylog.py fait la conversion automatiquement
